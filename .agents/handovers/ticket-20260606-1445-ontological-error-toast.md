## 1. Context & Forensic Findings

During testing after a clean system data reset, the workspace environment defaults to the `"platonic"` lobby scope. When a user interacts with the UI in this lobby state to switch viewport modes (Primordial, Being, or Realm) or attempts to log in as another being (such as July or Rob), a synchronous or asynchronous `Ontological Violation` error is thrown by the `session-service`.

### Detailed Diagnosis

1. **Rule 2 Check (Primordial Exclusivity):**
   In [session-service/activator.js](file:///Users/ddoegl/speckit/neverplayed/public/bundles/org.neverplayed.session-service/activator.js), the `login()` method enforces that only the Grounding Soul (e.g. `daniela`) can reside in the Platonic Staging Lobby. Shunting to viewport prefixes (`being:daniela` or `realm:daniela`) or logging in as another being resolves to identities distinct from the Grounding Soul, triggering an `Ontological Violation` error.

2. **Unhandled Shunt Rejections:**
   In [stratographer/activator.js](file:///Users/ddoegl/speckit/neverplayed/public/bundles/org.neverplayed.stratographer/activator.js), the `setShunt(type)` method calls `sess.login` synchronously without a `try/catch` block. This leads to immediate uncaught errors, halting execution and preventing visual state sync.

3. **Silent Promise Discarding in Stratum DOM:**
   In [stratum-core-dom/activator.js](file:///Users/ddoegl/speckit/neverplayed/public/bundles/org.neverplayed.stratum-core-dom/activator.js), the Alpine `stratum` store defines a `login(id, scope)` wrapper that forwards the invocation to the headless `_stratumSvc.login(id, scope)`. However, the store's wrapper function does not return the resulting Promise. Consequently, callers in the header or sidebar (like [shell-header/activator.js](file:///Users/ddoegl/speckit/neverplayed/public/bundles/org.neverplayed.shell-header/activator.js)) who await `stratum.login(id)` receive an immediate resolution of `undefined`, missing the subsequent asynchronous rejection entirely.

4. **Global Rejection Crash (Red Screen):**
   Because the rejection is not caught by the calling components, it bubbles up to the global window context. The entry [index.html](file:///Users/ddoegl/speckit/neverplayed/public/index.html) registers a global `"unhandledrejection"` listener. When it catches the uncaught rejection containing the term `"error"` or `"violation"`, it displays the critical "Catastrophic Kernel Failure" red screen, blocking user interaction and requiring a hard refresh.

## 2. Technical Objectives

### Objective 1: Retain and Return Login/Logout Promises
Update the Alpine `stratum` store definitions inside [stratum-core-dom/activator.js](file:///Users/ddoegl/speckit/neverplayed/public/bundles/org.neverplayed.stratum-core-dom/activator.js) so that the `login()` and `logout()` methods explicitly return the Promise generated by the underlying `_stratumSvc` service methods. This allows downstream consumer code to use `await` and capture errors within standard `try/catch` blocks.

### Objective 2: Guard UI Entry Points with try/catch
Add robust exception handling to the UI components triggering these logins:
1. In [stratographer/activator.js](file:///Users/ddoegl/speckit/neverplayed/public/bundles/org.neverplayed.stratographer/activator.js), wrap the `sess.login` and `sess.setBeingFocus` calls inside `setShunt(type)` in a `try/catch` block.
2. In [shell-header/activator.js](file:///Users/ddoegl/speckit/neverplayed/public/bundles/org.neverplayed.shell-header/activator.js), wrap `stratum.login` calls inside both `login(id)` and `identityLogin()` in `try/catch` blocks.

### Objective 3: Implement a Toast Notification System
Rather than fallback browser `alert()` popups, implement a modern, aesthetic toast overlay:
1. **Alpine Notification Store:** Register an Alpine global store (e.g., `notifications` or `toast`) to track a list of active toast items, their visual types (`error`, `success`, `info`, `warning`), visibility timers, and dismissal actions.
2. **Abstracted Interactor Integration:** In the browser implementation of the `INTERACTOR_SERVICE` (defined in [shared-ui/activator.js](file:///Users/ddoegl/speckit/neverplayed/public/bundles/org.neverplayed.shared-ui/activator.js)), expose a method to push notifications to this Alpine store, aligning with ADR-0029 (Universal Interactor Service).
3. **Glassmorphic Toast HUD:** Inject or mount a beautifully styled floating notification overlay container in the DOM (e.g. pinned to the bottom-right). Utilize Tailwind CSS glassmorphic backgrounds, subtle borders, high-contrast status icons, and Alpine-driven entrance/exit transitions.
4. **Error Redirection:** When an `Ontological Violation` or other recoverable runtime exception is caught by the UI controllers, direct the message to the toast interactor instead of allowing the promise to reject globally.
