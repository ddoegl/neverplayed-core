# Handover Ticket: Surrogate Augmentation via /level

**From:** Forensic Analyst (ana)
**To:** Development Engineer (dev)

## Context
A major architectural bug was discovered in how the `/level` command assigns perceptual modes. Currently, switching between beginner (Idealist) and advanced (Realist) levels creates an entirely new physical surrogate (e.g., `rob-advanced`). 

Because it replaces the user's active physical incarnation (e.g., `person`), the user loses access to realms like Governance that require the `person` surrogate privileges.

Per our architectural philosophy, **Surrogates** are physical incarnations (hardware) with intrinsic senses. **Levels/Grounding** are perceptual filters (software lenses) applied *through* that hardware. 

## Objectives
- [ ] **Refactor `/level` command:** In `org.neverplayed.shell-cli-ext/activator.js`, modify the `/level` command execution block.
- [ ] **Fetch Current Surrogate:** Instead of creating a new surrogate ID (`${user.id}-${targetLevel}`), retrieve the user's currently active surrogate object (e.g., `person` or `dog`).
- [ ] **Augment Senses:** Retain the surrogate's base ID. Strip out any previously applied perceptual senses (`IdealistVision`, `ForensicVision`, `ArchitectControl`), and merge in the new senses dictated by the target level.
- [ ] **Re-materialize:** Call `session.login(user.id, null, augmentedSurrogate)` using the modified surrogate object. Ensure the ID remains unchanged so realm privilege guards (like Governance) continue to recognize the physical incarnation.
- [ ] **Verify:** Ensure that executing `/level advanced` while logged in as `rob` maintains his identity as a `person` while successfully granting `ForensicVision`.
