# Handover Ticket: System Reset Regression

**From:** Forensic Analyst (ana)
**To:** Development Engineer (dev)

## Context
A major regression was discovered in the Data Reset flow. When a user triggers a factory reset, `org.neverplayed.system-reset/activator.js` delegates the wipe to the Persistence Manager (`await pm.clear()`). 

However, `persistence-localstorage` implements strict Sovereign Scoping in its `clear()` method, meaning it only deletes keys matching the current user's contextual prefix (e.g., `np:v1:tenant:realm:identity:`). 

Because the critical session state (`pandino.session.state`) is stored under a protected global bootstrap anchor (`np:v1:guest:unknown:guest:`), it completely survives the data reset. When the system reloads, it rehydrates corrupted session ghosts instead of booting fresh.

## Objectives
- [ ] **Refactor `system-reset`:** Open `public/bundles/org.neverplayed.system-reset/activator.js`.
- [ ] **Bypass OSGi Scoping:** Remove the logic that attempts to fetch the `PERSISTENCE_MANAGER_SERVICE` and call `pm.clear()`. 
- [ ] **Enforce Absolute Wipe:** Directly call `localStorage.clear()` to enforce a true, low-level factory reset that obliterates all traces and bootstrap anchors, ignoring contextual OSGi scopes.
- [ ] **Verify:** After applying the fix, ensure that clicking Data Reset permanently clears the `pandino.session.state` from the browser's application storage.
